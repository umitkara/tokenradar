# TokenRadar architecture summary

This is an English summary of the Turkish design documents (ADR-015). The full details are in
[`../architecture.md`](../architecture.md), the data sources in [`../data-sources.md`](../data-sources.md),
the decisions in [`../decisions.md`](../decisions.md) and the budgets in
[`../performance-budget.md`](../performance-budget.md).

## Process model

TokenRadar ships two binaries in one package:

| Binary | Subsystem | Role |
|---|---|---|
| `tokenradar-app.exe` | Windows GUI | The tray, the core, the IPC server and the windows. Shown as "TokenRadar". |
| `tokenradar.exe` | Console | The CLI: `statusline`, `status`, `limits`, `sessions`, `doctor`, `statusline install/uninstall`, `path add/remove`. |

The names differ because Windows file systems are case-insensitive (ADR-017). The installer puts the CLI in `bin\` and adds only that directory to the user `PATH`.

What always runs is a small Rust core and a tray icon drawn in Rust (tiny-skia). WebView2 windows (panel, settings, onboarding) are created on demand and destroyed a short "warm" time after they are hidden, so the memory cost is paid only while you look at a window. A second launch opens the panel instead of a new process.

```
Claude Code status line ──stdin JSON──▶ tokenradar.exe ──named pipe──▶ ┐
~/.claude/projects/**/*.jsonl ──file watcher──────────────────────────▶ │  tokenradar-core
~/.claude/sessions/*.json ──file watcher──────────────────────────────▶ │  (indexer, live sessions,
~/.claude/.credentials.json ──read-only, with consent─────────────────▶ │   limit engine, notifier,
api.anthropic.com ◀──usage poller, with consent──────────────────────── │   SQLite store)
                                                                        ┘
                    tray icon (Rust) + typed Tauri commands ──▶ panel / settings / onboarding (Svelte 5)
```

## Repository layout

| Path | What |
|---|---|
| `crates/tokenradar-core` | Domain, SQLite store, JSONL indexer, providers, limit engine, IPC protocol. No Tauri dependency. |
| `crates/tokenradar-i18n` | Fluent localization shared by the app and the CLI |
| `crates/tokenradar-cli` | The `tokenradar` console binary |
| `app/src-tauri` | The Tauri 2 shell: tray, windows, notifications, updater, installer template and hooks |
| `app/src` | Svelte 5 multi-page frontend; each window loads only its own bundle |
| `locales/{en,tr}` | Fluent files used by both Rust and TypeScript |

## Core components

- **Store:** SQLite in WAL mode with a single writer thread and readers; migrations, typed queries, retention (raw events 90 days, 5-minute rollups kept).
- **Indexer:** incremental JSONL reading by offset. Lines are pre-filtered with `memchr` and parsed with selective serde structs, so only usage and metadata fields are ever deserialized. Duplicates are merged with an order-independent rule.
- **Watcher:** debounced file events plus periodic stats and full scans, because Windows does not report watcher buffer overflows.
- **Live sessions:** reads Claude Code's session files and checks that their processes are alive.
- **Limit engine:** fuses the limit sources, tracks windows, and computes burn rate (Theil–Sen) and the projection of when a limit fills up.
- **Usage API poller:** the consent gate, read-only token use, adaptive intervals and backoff.
- **Notifier:** thresholds, projection, last warning and reset rules with hysteresis, deduplication and quiet hours.
- **IPC server:** a named pipe restricted to the current user's SID, rejecting remote clients; newline-delimited JSON.

The UI does no computation: Tauri commands return ready view models, and the frontend only draws them. The TypeScript bindings are generated by `tauri-specta`.

## Limit sources

| Source | What | Priority |
|---|---|---|
| Statusline | `rate_limits` in the JSON that Claude Code passes to its status line command | 1 |
| Usage API | `api.anthropic.com` usage endpoint, only with consent | 2 |
| Estimate | Derived from local logs; marked `≈`, never stored as a measurement | 3 |

For each limit the newest observation wins; within 30 seconds the higher-priority source wins. Readings older than 10 minutes show their age; after 30 minutes an estimate may take over, visibly labeled. When the CLI cannot reach the app, status line readings go to a spool file and are imported later, so the percentage history has no gaps.

The usage API is polled every 2 to 15 minutes depending on activity, at least 60 seconds apart, with jitter and exponential backoff. On a 401 the token is marked stale and TokenRadar waits until `.credentials.json` changes; it never refreshes the token.

## Privacy and security

- No telemetry. Network traffic goes only to `api.anthropic.com` (with consent) and GitHub Releases (the update check, which can be turned off).
- The access token is read only at request time, wrapped in a type that never prints, zeroized after use and never passed over IPC. The refresh token is never read.
- Conversation content is never read, stored or shown.
- The only file outside its own data that TokenRadar changes is Claude Code's `settings.json` (status line install): only after a click, with a diff, a backup and an atomic write. Only the `statusLine` member's bytes change, and uninstalling restores the file byte for byte.
- Updates are verified with a minisign signature; the release workflow checks that the signing key matches the public key shipped in the app.
- Lock files are committed; `cargo-deny` and `pnpm audit` run in CI.

## Files

| Item | Windows |
|---|---|
| Data (database, spool, logs) | `%LOCALAPPDATA%\TokenRadar\` |
| Settings | `%LOCALAPPDATA%\TokenRadar\config.toml` |
| Installed app | `%LOCALAPPDATA%\Programs\TokenRadar\` (CLI in `bin\`) |

With an empty `portable` file next to the app, everything goes to a `data\` directory beside it; the CLI in `bin\` finds the marker one level up.

## Localization

One source of truth: `locales/{en,tr}/*.ftl`, used by the Rust side (tray, notifications, CLI) and the TypeScript side (windows). Custom Fluent functions (`NUM`, `PCT`, `DUR`, and `TR_SUFFIX` for Turkish suffixes) behave identically in both languages' implementations and share test vectors. CI checks that every key exists in both languages.

## Performance budgets

Budgets are requirements, not goals. The main ones for v0.1: ≤ 25 MB of memory in the tray, ≤ 130 MB with the panel open, ≤ 30 MB shortly after all windows close, statusline command p95 < 30 ms, installer ≤ 12 MB. Measurements are recorded under [`../perf/`](../perf/).
